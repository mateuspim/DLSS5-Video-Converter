# DLSS 5 Media Converter

Локальный веб-инструмент для видео и статических изображений через **NVIDIA DLSS 5 Neural Rendering** (NGX feature 18, `nvngx_dlssnr.dll`). Видео использует motion vectors из optical flow и NVENC; изображения сохраняются в lossless PNG.

> **Экспериментально.** Это исследовательская сборка: модель DLSS Neural Rendering вызывается напрямую, вне игрового движка. Перед использованием прочитайте раздел [Ограничения](#ограничения).

---

## Что делает

1. Вы перетаскиваете видео или изображение в веб-интерфейс (или выбираете его кнопкой).
2. Каждый кадр декодируется, переводится в RGBA8 и отправляется в модель DLSS 5 Neural Rendering (feature 18) вместе с motion vectors, оценёнными по самому видео через optical flow.
3. Обработанные кадры кодируются NVENC (H.264 / HEVC / AV1) и склеиваются с оригинальным звуком и метаданными.
4. Результат попадает в `outputs/` вместе с JSON-отчётом, где зафиксированы все доказательства работы пайплайна (подтверждение feature 18, число успешных оценок кадров, SHA-256 модели, логи кодера).

PNG, JPEG и WebP обрабатываются как один reset-кадр с нулевым motion vector и сохраняются в lossless PNG. Настройки видеокодирования для изображений скрываются.

## Быстрый старт

**Требования:** Windows 10/11 64-bit, видеокарта NVIDIA RTX, свежий драйвер. Всё остальное (Python, FFmpeg, DLSS-рантайм) уже в комплекте — ничего устанавливать не нужно.

1. Запустите `start.bat`.
2. Откройте в браузере **http://127.0.0.1:7860**.
3. Перетащите видео в зону загрузки (или кликните по ней), выберите профиль и параметры кодирования, нажмите **Render whole video**.

Сервер слушает только `127.0.0.1` — интерфейс не доступен из сети.

## Возможности

### Профили

Готовые комбинации параметров Neural Rendering:

| Профиль | Intensity | Local Tone | Local Structure | Skin Structure |
| --- | --- | --- | --- | --- |
| Faithful | 0.70 | 0.75 | 0.75 | −1.0 |
| Natural | 1.00 | 1.00 | 1.00 | −1.0 |
| Strong / Cinematic | 1.65 | 1.40 | 1.50 | 1.0 |
| Extreme / Overdrive | 2.50 | 2.00 | 2.00 | 1.5 |

### NR Parameters (ручная настройка)

Четыре слайдера — **Intensity**, **Local Tone**, **Local Structure** (диапазон 0–3) и **Skin Structure** (диапазон −1 до 3), шаг 0.05. Движение любого слайдера переопределяет соответствующий параметр выбранного профиля.

### Кодирование

- **Кодеки:** H.264, HEVC, AV1 — через NVENC, когда доступен; H.264/HEVC при отсутствии NVENC откатываются на `libx264`/`libx265`. AV1 требует поддержки NVENC (программного запасного варианта нет).
- **Контейнеры:** MP4 (звук перекодируется в AAC 192 кбит/с, `+faststart`) или MKV (звук и субтитры копируются без перекодирования).
- **Качество:** High (CRF 17), Balanced (CRF 20), Small (CRF 24).

### Интерфейс

- Переключатель языка RU/EN, тёмная/светлая тема (обе запоминаются между сессиями).
- Drag & drop или выбор файла; поддерживаются mp4 / mkv / webm / png / jpg / jpeg / webp.
- Живой прогресс-бар, статус по кадрам, бейдж GPU (название + версия драйвера).
- Лента результатов с кнопками **Скачать** и **JSON** (отчёт), плюс предпросмотр последнего рендера прямо на странице.
- **Stop** отменяет текущий рендер (частичное видео удаляется, диагностика сохраняется); **Очистить** очищает ленту результатов.
- Одновременно выполняется только один рендер — интерфейс откажется запускать второй, пока идёт первый.

## Как это работает (пайплайн)

```
входное видео → анализ ffprobe → покадровое декодирование (PyAV)
    → кадры RGBA8 + motion vectors из optical flow (DIS, 640 px)
    → нативный воркер: прямой вызов feature 18 (nvngx_dlssnr.dll)
    → поток rawvideo → NVENC (H.264/HEVC/AV1)
    → склейка с оригинальным звуком и метаданными → outputs/<имя>_DLSS5_<штамп>.mp4|.mkv
    → проверка числа кадров + JSON-отчёт
```

- Motion vectors оцениваются оптическим потоком OpenCV DIS (от текущего кадра к предыдущему, в пикселях); детектор склеек сбрасывает темпоральное состояние, когда разница между кадрами превышает порог.
- Первые 120 кадров используются как прогрев модели.
- После склейки выходной файл проверяется заново: число кадров должно точно совпасть с отрендеренным, иначе задание падает — обрезанный файл не отдаётся.
- Каждый кадр обязан вернуть успешный результат feature 18; любая неудачная оценка останавливает рендер.

## Требования

| Компонент | Требование |
| --- | --- |
| ОС | Windows 10/11, 64-bit |
| GPU | NVIDIA RTX 40/50 серии (RTX 30 серия: **бета** — работает, но очень медленно) |
| Драйвер | Свежий драйвер NVIDIA (поддержка NVENC и NGX) |
| Память | Достаточно RAM для обрабатываемых кадров (для 4K нужно несколько гигабайт) |
| Сеть | Не нужна — всё работает локально |

При старте инструмент проверяет GPU через `nvidia-smi` и отказывается работать на не-RTX видеокартах. FFmpeg, встроенный Python и DLSS-рантайм поставляются в `bin/` — ничего в систему ставить не нужно.

## Ограничения (прочитайте)

- **Только SDR.** Проверенный путь DLSSNR рендерит в RGBA8. HDR-вход конвертируется в SDR, и выходной файл **не помечается** как HDR — сохранение HDR в этой сборке намеренно отключено, чтобы не выдавать результат за HDR.
- **Оценённые motion vectors.** Optical flow здесь вычисляется по самому видео и *не равен* движковым motion vectors, под которые модель проектировалась. На быстром движении, окклюзиях, тонких объектах и склейках возможны темпоральные артефакты.
- **Модифицированные бинарники.** `bin/runtime/nvngx.dll` — модифицированный шим (обёртка/воркер), а не ядро NVIDIA NGX. `nvngx_dlssnr.dll` — модифицированная сборка модели, пропатченная для standalone-вызова вне движка (включает проверку caller). Хэши и лицензии — в `others/THIRD_PARTY.md`.
- **Строгая политика отказов.** Если хотя бы один кадр не прошёл оценку feature 18, рендер отклоняется целиком. Это намеренно — непроверенный результат не отдаётся.
- **Медленный первый анализ.** На 4K-видео начальный анализ может занять 1–3 минуты: ffprobe декодирует все кадры, чтобы получить точное число.
- **Скорость.** Рендер покадровый, а оценка потока идёт на CPU — на длинных и высокобитрейтных видео время работы большое. RTX 30 серия — бета и очень медленная.
- **Одно задание за раз.** Очереди нет.

```
│   ├── core.py                # бэкенд: анализ, пайплайн feature 18, NVENC, отчёты
│   └── guides.py              # optical flow + детектор склеек

│   ├── ffmpeg/                # FFmpeg/ffprobe в комплекте
│   ├── python-3.13.15-embed-amd64/   # встроенный Python

├── outputs/                   # готовые видео + .report.json

```

## JSON-отчёт

Каждый успешный рендер пишет `<output>.report.json` рядом с видео. В отчёте: метаданные входа и выхода, выбранные опции, GPU, фактически использованный кодер, число кадров, сбросы склеек, затраченное время, средний FPS, подтверждение feature 18 (`feature_18_confirmed`, `direct_create_result`, `successful_direct_evaluations`), SHA-256 модели и воркера, а также сырые логи воркера и кодера.
